 ○  Categories:  CategoryId(int)  PK  ○  AuditsLogs:  AuditLogId(int)  PK,  AdminId(int)  FK(Users)

for
 
each
 
entry.
 ○  All  the  tables  are  normalized  to  max  to  keep  data  integrity  and  prevent  
inconsistencies.
 ●  Access  Rights  restrict  unauthorized  modifications.  ○  Use  of  JWT  to  keep  all  the  actions/URL  of  api  authorization  restricted.

13.  System  Security  Measures  
●  JWT  Authentication  for  API  security.  
Why?  
●  Ensures  secure  communication  between  the  front-end  (React)  and  back-end  
APIs.
 ●  Prevents  unauthorized  access  to  protected  routes.  ●  Reduces  risk  of  session  hijacking  compared  to  traditional  session-based  
authentication.
 
Implementation  in  Our  System:  
●  When  a  user  (Organizer  or  Participant)  logs  in,  the  backend  generates  a  JWT  
(JSON
 
Web
 
Token)
 
and
 
sends
 
it
 
to
 
the
 
front-end.
 ●  The  front-end  stores  the  JWT  securely  in  HTTP-only  cookies  or  local  storage  
(with
 
added
 
security).
 ●  Every  API  request  from  the  front-end  includes  the  JWT  in  the  Authorization  
header
 
(Bearer
 
Token)
 
for
 
authentication.
 ●  The  backend  verifies  the  token  using  a  secret  key  before  granting  access  to  
protected
 
resources.
 
 ●  Role-based  access  control .  
Why?  
●  Ensures  users  can  only  access  functionalities  relevant  to  their  role  (Organizer  
or
 
Participant).
 ●  Prevents  unauthorized  users  from  performing  restricted  actions  (e.g.,  a  
Participant
 
creating
 
events).
 
Implementation  in  Our  System:  
●  Define  roles  in  the  database  (Organizer,  Participant,  Admin).  ●  When  generating  JWTs,  embed  role  information  inside  the  token.  ●  Implement  middleware  on  the  backend  that  checks  roles  before  granting  
access
 
to
 
API
 
endpoints.
 ●  Front-end  components  (React)  conditionally  render  UI  elements  based  on  user  
roles
 
(e.g.,
 
only
 
Organizers
 
see
 
"Create
 
Event"
 
button).
 
Example:  
●  Participant  Role:  Can  view  &  RSVP  to  events  but  cannot  manage  or  create  
events
.

Appendix  C:  Development  Methodology  
The  development  process  followed  an  Agile  approach,  with  iterative  releases  and  
continuous
 
feedback.
 
1.  Planning  Phase:  
 ○  Defined  user  roles  (Organizer,  Participant).  ○  Identified  core  functionalities .  ○  Created  wireframes  for  UI  design.  2.  Development  Phase:  
 ○  Implemented  backend  APIs  for  authentication,  event  management,  and  
user
 
roles.
 ○  Built  a  responsive  UI  using  React.js  &  Tailwind  CSS.  ○  Integrated  frontend  with  backend  via  REST  APIs .  3.  Testing  &  Debugging:  
 ○  Performed  unit  testing  for  API  endpoints.  ○  Conducted  UI  testing  for  responsive  behavior.  4.  Deployment  &  Hosting:  
 ○  Deployed  backend  on  AWS  EC2  with  a  SQL  Server  database  on  RDS.  ○  Hosted  the  React  app  on  AWS  S3  +  CloudFront .  
 
Appendix  D:  Security  Measures  
1.  JWT  Authentication  
 ○  Protects  API  endpoints  using  JWT  tokens .  ○  Implements  token  expiration  &  refresh  strategies.  2.  Role-Based  Access  Control  (RBAC)  
 ○  Organizers  can  create  &  manage  events.  ○  Participants  can  view  &  RSVP  for  events.  3.  AWS  Secrets  Manager  
 ○  Ensures  safe  storage  of  database  credentials  and  API  keys.  4.  Best  Practices  Implemented  
 ○  HTTPS  enforcement  for  secure  connections.  ○  Input  validation  to  prevent  SQL  injection  &  XSS  attacks.  ○  Rate  limiting  for  API  protection.
